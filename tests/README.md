# CITEgeist Test Suite

Comprehensive test suite for the CITEgeist spatial transcriptomics deconvolution framework.

## Overview

This test suite provides extensive coverage of CITEgeist functionality including:

- **Unit Tests**: Test individual functions and components in isolation
- **Integration Tests**: Test interactions between components
- **Fixtures**: Reusable test data and mock objects

## Test Structure

```
tests/
├── conftest.py              # Pytest configuration and shared fixtures
├── test_utils.py            # Tests for utility functions
├── test_checkpoints.py      # Tests for checkpoint management
├── test_model.py            # Tests for model preprocessing and core functionality
├── test_gurobi_impl.py      # Tests for optimization (mocked, no Gurobi required)
├── test_integration.py      # Integration tests for full pipeline
└── README.md                # This file
```

## Running Tests

### Run All Tests

```bash
pytest
```

### Run Specific Test Categories

```bash
# Run only unit tests
pytest -m unit

# Run only integration tests
pytest -m integration

# Run tests excluding slow tests
pytest -m "not slow"

# Run tests that don't require Gurobi
pytest -m "not requires_gurobi"
```

### Run Tests with Coverage

```bash
# Generate coverage report
pytest --cov=CITEgeist/model --cov-report=html

# View coverage in browser
open htmlcov/index.html
```

### Run Tests in Parallel

```bash
# Run tests in parallel using multiple CPU cores
pytest -n auto
```

## Test Markers

Tests are organized using pytest markers:

- `@pytest.mark.unit`: Unit tests for individual functions
- `@pytest.mark.integration`: Integration tests for component interactions
- `@pytest.mark.slow`: Tests that take a long time to run
- `@pytest.mark.requires_gurobi`: Tests that require Gurobi license (skipped by default)
- `@pytest.mark.requires_data`: Tests that require actual data files

## Test Fixtures

Common fixtures are defined in `conftest.py`:

### Data Fixtures
- `mock_gex_adata`: Mock gene expression AnnData object
- `mock_protein_adata`: Mock protein/antibody capture AnnData
- `mock_combined_adata`: Combined gene + protein AnnData
- `mock_cell_profile_dict`: Cell type profile dictionary
- `mock_cell_proportions`: Ground truth cell proportions

### Utility Fixtures
- `temp_output_dir`: Temporary directory for test outputs
- `sample_name`: Standard sample name for tests
- `mock_gurobi_license`: Mock Gurobi license file
- `mock_ground_truth_layers`: Mock ground truth expression layers

## Writing New Tests

### Example Unit Test

```python
import pytest
from CITEgeist.model.utils import benchmark_cell_proportions

@pytest.mark.unit
def test_benchmark_perfect_prediction(cell_type_names):
    """Test benchmarking with perfect predictions."""
    true_props = np.random.dirichlet(np.ones(9), size=100)
    pred_props = true_props.copy()

    results = benchmark_cell_proportions(true_props, pred_props, cell_type_names)

    assert results['JSD'] < 0.01
    assert results['corr'] > 0.99
```

### Example Integration Test

```python
import pytest
from CITEgeist.model.citegeist_model import CitegeistModel

@pytest.mark.integration
def test_full_pipeline(temp_output_dir, sample_name, mock_gex_adata,
                      mock_protein_adata, mock_cell_profile_dict):
    """Test complete pipeline workflow."""
    model = CitegeistModel(
        sample_name=sample_name,
        output_folder=temp_output_dir,
        simulation=True,
        gene_expression_adata=mock_gex_adata,
        antibody_capture_adata=mock_protein_adata
    )

    model.load_cell_profile_dict(mock_cell_profile_dict)

    assert model.cell_profile_dict is not None
```

## Coverage Goals

Target coverage thresholds:

- **Overall**: ≥ 60% (enforced in CI)
- **Utils module**: ≥ 80%
- **Checkpoints module**: ≥ 85%
- **Model module**: ≥ 70%
- **Integration coverage**: Key workflows tested

## Continuous Integration

Tests run automatically on:
- Push to `main`, `develop`, or `claude/*` branches
- Pull requests to `main` or `develop`

CI workflow:
1. Runs unit tests
2. Runs integration tests
3. Generates coverage report
4. Uploads coverage to Codecov
5. Fails if coverage drops below 60%

## Test Data

Tests use simulated data generated by fixtures. No real patient data is used in tests.

- **Simulated spots**: 100 (default for speed)
- **Simulated genes**: 200
- **Simulated proteins**: 18 (9 cell types × 2 markers)
- **Cell types**: 9 (B-cells, CAFs, Cancer Epithelial, Endothelial, Myeloid, Normal Epithelial, PVL, Plasmablasts, T-cells)

## Troubleshooting

### Tests Fail Due to Missing Dependencies

```bash
pip install -r requirements-dev.txt
```

### Gurobi-Related Test Failures

Tests requiring Gurobi are skipped by default. To run them:

1. Install Gurobi
2. Set up Gurobi license
3. Run: `pytest -m requires_gurobi`

### Slow Test Performance

Run tests in parallel:
```bash
pytest -n auto
```

Or exclude slow tests:
```bash
pytest -m "not slow"
```

### Coverage Not Generating

Ensure pytest-cov is installed:
```bash
pip install pytest-cov
```

## Best Practices

1. **Isolation**: Each test should be independent
2. **Fixtures**: Use fixtures for common test data
3. **Markers**: Mark tests appropriately (unit, integration, slow, etc.)
4. **Assertions**: Use clear, specific assertions
5. **Documentation**: Include docstrings for test functions
6. **Speed**: Keep unit tests fast; mark slow tests appropriately
7. **Coverage**: Aim for high coverage but prioritize important code paths

## Contributing

When adding new features:

1. Write tests first (TDD approach)
2. Ensure tests pass locally
3. Check coverage with `pytest --cov`
4. Update this README if adding new test categories
5. CI must pass before merging
